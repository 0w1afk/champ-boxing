Ты оркестратор процесса из docs/process/workflow.md. Прочитай его и docs/process/status.md, затем выполни команду: $ARGUMENTS

Состоянием управляет только скрипт, ниже он обозначен как `gate`:

```bash
node .agents/skills/pipeline/scripts/gate.mjs <команда>
```

Он записывает docs/process/status.json и генерирует docs/process/status.md. Не редактируй эти файлы вручную. Если скрипт вернул «ЗАБЛОКИРОВАНО», покажи пользователю причины дословно и устрани их. Обходить блокировку запрещено: ни правкой файлов, ни выполнением этапа без перехода.

Снятие пункта чек-листа через `gate item s9 <пункт> --undo` делает G4 устаревшим. Даты скрипт фиксирует по Москве (`Europe/Moscow`).

## Команды

- **status** или пусто: выполни `gate status`, покажи текущий гейт, что ждёт утверждения и что блокирует работу. Ничего не меняй.
- **next**: выполни ровно один следующий гейт:
  1. Определи его по `gate status`.
  2. Выполни `gate start <гейт>`. Если заблокировано, остановись.
  3. Выполни работу сам (основная сессия); изображения — только через `node .agents/skills/pipeline/scripts/image.mjs`.
  4. Запусти субагента `reviewer` (`.opencode/agent/`) — один проход перед утверждением; правки по находкам сделай сам, затем ревьюер перепроверяет.
  5. Выполни `gate submit <гейт> --material <путь>`. Обязательные файлы скрипт добавит сам и проверит.
  6. Покажи результат и остановись. Следующий гейт не начинай.
- **approve <гейт>**: выполни `gate approve <гейт> --evidence "дословная фраза пользователя"`. Следующий гейт не запускай.
- **rework <гейт> <что изменить>**: выполни `gate rework <гейт> --reason "что изменить"`, покажи список устаревших гейтов и сделай правку сам.

## Правила

1. Утверждение ставится только по явному слову пользователя именно об этом гейте. Молчание, «вроде нормально» и твоя уверенность утверждением не считаются. В `--evidence` передавай его слова дословно. Если ответ неоднозначен, переспроси. `approve` не запускается в том же ходе, что и `submit`, если только пользователь уже не увидел материалы и не утвердил их.
2. Субагенты — по необходимости: ревьюер перед каждым `submit`; остальные роли (.opencode/agent/) только для крупных самостоятельных блоков работы.
3. Интервью и выбор концепции веди сам в основной сессии: там есть прямая связь с пользователем.
4. Изображения — только через `image.mjs` (ChatGPT). Сгенерированное изображение покажи пользователю до использования.
5. После утверждения G3 проект в режиме итераций: правки без гейтов, коммит — по явной просьбе.
6. Показывая результат на гейт, давай: что сделано, ссылки, что именно утвердить, замечания проверок и варианты, если они есть.
